# iod — RFNM board I/O daemon

Drives the RFNM Blue motherboard's bottom-edge I/O header. Talks the kernel GPIO chardev
uapi v2 directly (`/dev/gpiochipN` + ioctls) — no libgpiod dependency, static-friendly.
Requested lines are held while the daemon runs so output values persist; released lines
revert to hi-Z. Pins whose pad is not owned by the device tree can be runtime-muxed
between their primary function (e.g. PWM3_OUT) and GPIO.

Pins listed in the `IO_GUARD` set of `/rfnm/board.conf` are rendered read-only: `iod`
never requests them as outputs and `/set` refuses them — a deployment can reserve header
pins for external equipment that must not be flipped from a web page.

## HTTP API

JSON over HTTP on `127.0.0.1:7691`, published by the on-board nginx as
`/api/app/boardio/` (route generated by appd from the manifest):

- `GET /status` → `{"pins":[{id,chip,line,label,silk,dir,val,guarded,planned}...]}`
- `POST /set` → `{"id":"gpio1_10","dir":"out","val":1}` or `{"id":...,"dir":"in"}`

## Build / test

```sh
make                      # host or cross (no dependencies beyond the kernel uapi)
make selftest             # ./iod --selftest; RFNM_IOD_MOCK=1 skips the chardev
```

Cross build: aarch64 with `ARCHFLAGS=-mcpu=cortex-a53`, or simply
`./rfnm-sdk build apps` from [github.com/rfnm/sdk](https://github.com/rfnm/sdk).

## Run

Deploys to `/rfnm/apps/boardio/` and runs as a systemd service; it is `radio:"none"`
(never takes the radio lease) so it can run alongside any radio app. Start it via appd or
`systemctl start` — never enable per-app units by hand.
